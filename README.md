# cs433_project1
Repository for CS-433 Machine Learning Project 1

Team project for the EPFL Machine Learning course. We predict whether a person has
coronary heart disease / has had a heart attack (`_MICHD`) from the BRFSS 2015
health-survey data.

## Repository structure

```
cs433_project1/
├── implementations.py           # the six required ML methods + helpers + k-fold CV
├── run.py                        # trains the six methods, selects the best, writes submission.csv
├── project1_preprocessing.ipynb  # Phase 1: cleaning/encoding + EDA -> writes preprocessed.npz
├── leastsquares_ridgereg.ipynb   # experiments: least squares, ridge
├── README.md
├── helpers.py                    # course-provided load_csv_data  (NOT committed, add manually)
├── submission.csv                # produced by run.py
├── result/                       # produced by run.py (per-method predictions, scores.json)
└── data/
    └── dataset/
        ├── x_train.csv           # NOT committed, download from AIcrowd
        ├── y_train.csv           # NOT committed
        ├── x_test.csv            # NOT committed
        └── preprocessed.npz      # generated by project1_preprocessing.ipynb
```

| File | Description |
|------|-------------|
| `implementations.py` | The six required ML methods, plus helpers (loss, gradient, sigmoid) and k-fold cross-validation. |
| `project1_preprocessing.ipynb` | Phase 1: cleans and encodes the raw data (with exploratory analysis and figures) and writes `preprocessed.npz`. |
| `run.py` | Loads `preprocessed.npz`, trains the six methods with 5-fold CV, selects the best by F1, and writes `submission.csv`. |
| `README.md` | This file. |

`helpers.py` (the course-provided `load_csv_data`) is **not committed**. Copy it from the
course `projects/project1` folder into the repository root — the preprocessing notebook
imports it to read the raw CSVs.

## Requirements

No other external libraries are used, as required by the project rules.

## Getting the data

The dataset is **not** included in the repository. Download the three CSV files from the
AIcrowd challenge
[EPFL ML Project 1](https://www.aicrowd.com/challenges/epfl-machine-learning-project-1)
and place them, with their original names, in `data/dataset/`:

```
data/dataset/x_train.csv
data/dataset/y_train.csv
data/dataset/x_test.csv
```

## Reproducing our submission

1. Place the three CSV files as described above, and copy `helpers.py` into the repository root.
2. Open `project1_preprocessing.ipynb`, set `DATA_DIR = "data/dataset"`, and run all cells.
   Its final cell writes `data/dataset/preprocessed.npz` (the cleaned, encoded and
   standardized train/test matrices).
3. Run the model script:
   ```
   python run.py
   ```
   It performs 5-fold cross-validation for the six methods, prints their F1 scores, refits
   the best method on all training data, and writes `submission.csv` (the file uploaded to
   AIcrowd). All random seeds are fixed, so the output is reproducible.

## Pipeline

### Preprocessing (`project1_preprocessing.ipynb`)

All decisions are rule-based (from the BRFSS 2015 codebook, missingness, and duplicate
checks); no model is used in this phase.

1. **Consistency checks** — matching sample/feature counts, aligned IDs, labels in {-1, 1}.
2. **Remove non-health and leakage columns** — survey bookkeeping (dates, IDs, weights,
   phone logistics) and `HAREHAB1` (cardiac rehab, only recorded for positives).
3. **Fill skip-pattern follow-ups** — e.g. `BPMEDS`, `DIABAGE2` (→ years with diabetes),
   filled as "not applicable" before the missing-value filter.
4. **Drop columns > 50% empty** in both train and test with matching missing rates.
5. **Remove redundant features** — keep one column per meaning (verified with a
   functional-dependency check); e.g. keep kg over pounds, exact age over age bins.
6. **Recode special codes** — 7/77 = don't know, 9/99 = refused → missing; 88 = none → 0.
7. **Encode and standardize** — one-hot for nominal variables, 0/1 for yes/no, median
   imputation plus "was-missing" indicators; all statistics are fit on train only.

Result: 321 raw features → 133 encoded columns, saved to `preprocessed.npz`.

### Methods (`implementations.py`)

The six required functions, each returning `(w, loss)`:

- `mean_squared_error_gd(y, tx, initial_w, max_iters, gamma)`
- `mean_squared_error_sgd(y, tx, initial_w, max_iters, gamma)`
- `least_squares(y, tx)`
- `ridge_regression(y, tx, lambda_)`
- `logistic_regression(y, tx, initial_w, max_iters, gamma)`
- `reg_logistic_regression(y, tx, lambda_, initial_w, max_iters, gamma)`

### Model selection (`run.py`)

`run.py` loads `preprocessed.npz`, so the preprocessing notebook must be run first. Each
method is evaluated by 5-fold cross-validation (`build_k_indices`, `cross_validation`,
`cross_validation_score` in `implementations.py`), scored by F1 with the rule
`predict +1 when tx @ w >= 0` (the same rule used for the test predictions). The method
with the best average cross-validation F1 is refit on the full training set and used to
produce `submission.csv`.

## Reproducibility notes

- `run.py` requires `data/dataset/preprocessed.npz`; generate it by running the
  preprocessing notebook once (step 2 above).
- All random seeds are fixed (`np.random.seed(433)` before each fit; `SEED = 1` for the
  cross-validation folds), so `run.py` produces the same `submission.csv` on every run.
